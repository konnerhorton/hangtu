# Synthetic AGS4 test files

Made-up data for the M5 ingest tests (`docs/data/ingest.md` §11), the M6 QC tests (`docs/data/qc.md` §8) and the M7 dataset tests (`docs/data/datasets.md` §12). No company data (SPEC §12.3).
AGS files can't hold comments, so this page says what each one is for.

The files are written by `_make_files.py` from hand-typed SI data. All but `defects.ags` pass python-ags4 with no errors, and the good files (`site_si.ags`, `site_us.ags`, `site_v404.ags`) stay QC-clean: no errors or warnings (`qc.md` §9 #2). Change the data there and rerun it, rather than editing a file:

    uv run python tests/data/ags/_make_files.py

`tests/ags/test_files.py` fails if a committed file differs from what the script writes.

**Adding a group to the good files** also changes, besides its own tests: the group lists in `tests/test_project.py` and `tests/ags/test_ingest_acceptance.py` (the groups the 4.0.4 file shares), the pcf headings in `tests/ags/test_units.py`, the flags in `tests/ags/test_values.py`, and record counts in `tests/qc/`. Check each group and heading against the 4.0.4 dictionary before adding it to `site_v404.ags`, and put a new specimen's group before any the 4.0.4 file lacks, or the specimen keys of the two files stop matching (M17 a).

UNIT, TYPE and ABBR are written after the data groups, so a group, unit or code added to a file doesn't move the lines of the data before it, which the tests name (M14).
